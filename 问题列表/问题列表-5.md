# 问题列表-5

## 背景

你要求基于 v2 文档（yudao 单体 + Postgres）从 0 落地单机 MVP，并优先跑通两个场景端到端闭环（MARKET_ANALYSIS + PROFIT_MODEL）。

当前仓库仅有文档，尚无任何 Java/Python/Vue/deploy 工程脚手架，需要先确定几个“落地必须的前置决策”，避免我一口气写完结果与你的预期不一致。

## 讨论问题（请按编号选择）

1. yudao 单体脚手架与 Vue3 管理端，你希望我如何获取？
   - A. 允许联网直接 git clone 官方仓库作为起点（推荐）
   - B. 不允许联网（则我用纯 Spring Boot + 轻量 Vue3 自建最小脚手架，接口/表结构严格按 v2 文档）
   - C. 允许联网，但你指定仓库地址/分支（更可控）

2. Java 控制面与 yudao 的“严格度”你希望怎样？
   - A. 必须使用 yudao 单体落地（允许我做 Postgres 适配与裁剪）
   - B. 允许先用纯 Spring Boot 实现控制面（功能/接口/表结构按 v2 文档），后续再迁移到 yudao
   - C. 由我评估后决定（以尽快跑通闭环为准）

3. LLM Provider（SiliconFlow）你希望本期怎么处理？
   - A. 直接接真实 SiliconFlow（你会提供环境变量 SILICONFLOW_API_KEY）
   - B. 先做 Mock Provider（固定输出，不依赖 Key；推荐用于先跑通链路）
   - C. 两者都做：默认 Mock，可切换 SiliconFlow

4. web-admin（Vue3 管理端）本期交付范围你希望到哪一步？
   - A. 本期先不做前端，只做后端 API + Swagger/接口文档（推荐：先跑通闭环）
   - B. 做最小可用管理端：任务列表/任务详情/流式输出/配置页
   - C. 你已有现成前端仓库/模板，我按它对接后端 API
