# 问题列表-4

## 背景

你希望 Java 控制面尽量基于成熟脚手架（参考 yudao-cloud），并采用前后端分离（前端 Vue3）。

由于 yudao-cloud 属于 Spring Cloud 微服务脚手架，默认基础设施与我当前单机 MVP 方案（Java 控制面 + Python 执行面 + Postgres/Redis/MinIO）在技术栈上可能存在冲突（例如数据库、注册配置中心、服务数量与资源占用）。

为避免“脚手架选了但落地成本爆炸”，需要先确定选型边界。

## 讨论问题（请按编号选择）

1. 后端脚手架你希望选哪种路线？
   - A. yudao-cloud（Spring Cloud 多服务）
   - B. yudao-framework/单体版（推荐：更适合单机4C16G先跑通）
   - C. 自建 Spring Boot（只引入你需要的组件）
   - D. 先保持现有技术方案不变，仅参考其代码风格/模块结构

2. 数据库你更倾向哪种？
   - A. 保持 Postgres（与现有技术方案一致）
   - B. 切换 MySQL（推荐：与 yudao 默认更贴合，改造成本低）
   - C. 两者都行，由我推荐并给出取舍

3. 你对“服务拆分”的接受度？
   - A. 单机阶段必须单体（推荐：更稳、更省运维）
   - B. 单机阶段也可以多服务（只要能跑起来）
   - C. 先单体，后续再平滑拆分为多服务

4. 前端你希望怎么做？
   - A. 直接使用 yudao 的 Vue3 管理后台前端作为起点（推荐：最快出管理台）
   - B. 自己写 Vue3，但参考 yudao 的页面/组件与权限路由
   - C. 先不做前端，只做后端 API + 简单页面（MVP更快）

## 回复方式

请直接按编号回复，例如：`1B 2B 3C 4A`。

## 本轮已确认答案

- 1A：采用 `yudao-cloud 多服务` 路线
- 2B：数据库 `切换 MySQL`
- 3A：单机阶段 `单体` 优先
- 4A：前端 `直接使用 yudao Vue3 管理端` 作为起点
