目标：在不新增 Postgres/Redis 的前提下，让 crob-ai-agent 在“本地启动/容器启动”两种方式下都能稳定连接你现有的基础设施（D:\work\docker\infrastructure）。

### 1) Postgres 访问方式（用于 Java/Python 本地启动）
- A. 通过宿主机端口访问：127.0.0.1:5432
- B. 通过 Docker network 服务名访问：postgres:5432
- C. 两种都要支持（本地启动用 A；容器启动用 B）

### 2) crob_agent 数据库的创建方式
- A. 你已经手工创建好了 crob_agent（我只需要配置连接信息）
- B. 允许我提供 SQL，你来执行创建 crob_agent（owner=postgres）
- C. 希望我在我们的 compose 里提供一个一次性 init 容器去执行（但仍复用你现有的 postgres 容器）

### 3) Redis 连接信息确认（用于 Java/Python）
- A. requirepass=1qaz@WSX + DB=1（按我们当前对齐的结论）
- B. requirepass=1qaz@WSX + DB=0
- C. 无密码 + DB=1
- D. 其他（你补充实际值）

### 4) 你的 infrastructure Docker 网络信息（用于我们容器加入同网段访问 postgres/redis）
- A. 允许我把我们的服务加入你现有 compose 创建的默认 network（需要你告诉我 network 名称）
- B. 你有一个明确的 external network 名称（直接告诉我 network 名称，我在我们的 compose 里 external 引用它）
- C. 我不希望我们的容器加入你的 network（那我们只走“本地进程访问 127.0.0.1”模式）

## 已确认结论（来自本次问答）
- Postgres：两种都支持（本地启动用 127.0.0.1:5432；容器启动用 docker network 服务名 postgres:5432）
- crob_agent：你已创建好（我只需要对齐连接与 schema 初始化脚本）
- Redis：requirepass=1qaz@WSX，使用 DB=1
- 容器网络：需要加入你现有 infrastructure 的 external network（名称见 问题列表-12）
